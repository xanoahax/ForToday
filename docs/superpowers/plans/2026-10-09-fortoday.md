# ForToday Implementation Plan

> Ausführung: inline mit superpowers:executing-plans. Der Nutzer fordert eine funktionierende App im ersten Durchlauf.

**Goal:** Schmale Windows-App mit Listen pro Tag oder Titel, optionalen Zeiten und sicherem JSON-Speicher.
**Architecture:** Reines Modell → atomarer Dateispeicher → isolierte Electron IPC → lokale UI.
**Tech Stack:** Electron, Vanilla JS/CSS, Node test, Playwright, electron-builder.
**Spec:** ../specs/2026-10-09-fortoday-design.md

## Global Constraints
- 420 × 780 px, Light Mode, deutsche UI, keine Cloud und keine Beispieldaten.
- Datum immer lokal; ein Datensatz pro Tagesliste.
- Änderungen vor Erfolgsanzeige schreiben, Import validieren und absichern.

## Review Focus
- Tageswechsel/Zeitzone: lokales Datum und aktualisierte Hervorhebung (Task 3).
- Ungültige Zeiten/Daten/Importe: ablehnen ohne Datenverlust (Task 1).
- Unterbrochenes Schreiben/beschädigtes JSON: vorherige Daten erhalten (Task 2).
- Lange Texte und viele Aufgaben: umbrechen, scrollen, Eingabe erreichbar (Task 3).
- Neustart und schnelle Aktionen: alles genau einmal persistiert (Tasks 2/3).

## Task 1: Datenmodell

- [x] Tests zuerst: Tag/Kalendervalidierung, Duplikatdatum, Task-CRUD, optionale Dauer und Import.

## Prüfprotokoll
- 12 Node-Tests grün: CRUD, Schema, Kalenderdaten, Dauer, Import, Datei-Neustart, Backup-Recovery, Schreibfehler, Importgrößenlimit, Backup-Rotation und Undo.
- Electron-End-to-end grün: tägliche/eigene Listen, Enter, Dauer, Bearbeiten, Löschen/Undo, Import/Export, Backup, Neustart, lokale Datumsänderung, 360-Pixel-Fenster, lange Texte und Markup als Klartext.
- Unabhängige Review: Größenlimit vor jedem Schreiben durchgesetzt; Statusmeldungen innerhalb modaler Ebene angezeigt. Beide Korrekturen durch Reviewer nachgeprüft, keine verbleibenden Blocker.
- npm audit --omit=dev: 0 Schwachstellen. Build-Werkzeuge enthalten 8 moderate Meldungen in transitiven Entwicklungsabhängigkeiten; sie sind nicht in der ausgelieferten App enthalten.
- Ausführung direkt im leeren Nutzerprojekt. Kein vorhandenes Git-Repository, daher kein Branch/Merge notwendig.
- Portable-EXE-Smoke-Test grün: release/ForToday.exe gestartet, Aufgabe angelegt, JSON auf Festplatte geprüft, App geschlossen und erneut gestartet; gespeicherte Aufgabe vorhanden. Testprofil anschließend entfernt.
